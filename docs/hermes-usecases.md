# Hermes Agent 유스케이스 가이드

> 운전선생 전 팀원용 — 슬랙 봇한테 뭘 시킬 수 있는지 총정리

Hermes는 슬랙 DM으로 AI에게 업무를 요청하는 에이전트입니다.
터미널을 열 필요 없이, 슬랙에서 자연어로 대화하면 됩니다.
이 문서는 "뭘 시켜야 할지 모르겠다"는 분들을 위한 실전 레시피입니다.

> 📝 **새 유스케이스 추가하려면**: 이 파일 직접 편집 → PR 또는 슬랙 #ai-native-camp 에 텍스트로 공유

---

## 🌱 처음이라면 — 이 3개부터 (Quickstart)

신규 팀원/캠프 못 받은 분은 **아래 3개만 먼저** 슬랙에서 봇에게 던져보세요. 5분 안에 Hermes가 어떤 도구인지 체감합니다.

1. `@hermes-bot 오늘 할 일 정리하고 우선순위 매겨줘`
2. `@hermes-bot [긴 문서 붙여넣기] 한 줄로 요약해줘`
3. `@hermes-bot 고객한테 [상황] 답변 초안 써줘`

이 3개가 익숙해지면 아래 카테고리(직무별 시나리오) 로 넘어가세요.

## 3. 자동화 — cron 예약 (Hermes 킬러 기능)

Hermes의 가장 강력한 기능입니다. 정해진 시간에 자동으로 메시지를 보내줍니다.
슬랙 봇한테 자연어로 말하면 cron 스케줄을 만들어주지만, `/cron` 명령어로 직접 관리할 수도 있습니다.

### 매일 아침 브리핑

```
/cron add 0 9 * * 1-5 오늘 할 일 목록 정리해서 알려줘. 어제 마무리 못한 것도 포함.
```

또는 자연어로:

```
매일 아침 9시에 오늘 할 일 브리핑해줘. 주말은 빼고.
```

### 주간 보고서 초안

```
/cron add 0 17 * * 5 이번 주에 내가 요청한 것들 정리해서 주간 보고서 초안 만들어줘.
```

### 일일 뉴스 브리핑

```
/cron add 0 8 * * 1-5 AI/SaaS 업계 주요 뉴스 3개 찾아서 한국어로 요약해줘.
```

### 월요일 아침 주간 플래닝

```
/cron add 0 9 * * 1 이번 주 계획 세우는 걸 도와줘. 지난주 금요일에 정리한 내용 기반으로.
```

### 스탠드업 리마인더

```
/cron add 30 9 * * 1-5 스탠드업 시간이야! 어제 한 일, 오늘 할 일, 블로커 양식으로 작성 도와줘.
```

### cron 관리 명령어

```
/cron list
```

```
/cron remove [ID]
```

```
/cron pause [ID]
```

```
/cron resume [ID]
```

> cron 팁: 처음엔 자연어로 말해보고, 원하는 시간이 정확하면 `/cron add` 명령어로 직접 설정하세요.

### 회의록 정리

```
아래 회의 내용 정리해줘:

[회의 메모나 녹취 텍스트 붙여넣기]

```

function calculateDiscount(price, tier) {

## 6. 멀티 에이전트 — 봇끼리 대화, 프로필 기능

### 봇 프로필 설정

Hermes는 "나"를 학습합니다. 먼저 프로필을 알려주면 더 정확한 답변을 줍니다.

```
내 프로필 기억해줘:
- 이름: [이름]
- 직무: [직무]
- 팀: [팀명]
- 주로 쓰는 도구: Figma, Notion, Slack, VS Code
- 선호하는 답변 스타일: 간결하게, 불릿 포인트로
```

### 전문가 페르소나 요청

```
지금부터 시니어 백엔드 개발자처럼 답변해줘.
기술 스택: Node.js, PostgreSQL, AWS
코드 리뷰할 때 보안, 성능, 가독성 순서로 피드백.
```

```
지금부터 UX 리서처처럼 답변해줘.
사용자 인터뷰 질문을 만들고, 인사이트를 뽑는 데 집중.
```

### 멀티 에이전트 시나리오

여러 명이 같은 워크스페이스에 Hermes를 설치했다면, 각자의 봇이 독립적으로 동작합니다.
팀에서 이렇게 활용할 수 있습니다:

```

[팀원 1]: 온보딩 자동화

## 7. MCP 연동 — GitHub, Notion, DB 등

Hermes는 MCP(Model Context Protocol) 서버를 연결하면 외부 도구에 직접 접근할 수 있습니다.
설정은 `~/.hermes/config.json`에서 합니다.

### GitHub 연동

MCP 설정 후 사용 가능한 요청들:

```
우리 레포에서 열린 PR 목록 보여줘.
```

```
이 PR의 변경 내용 요약해줘: #42

### MCP 설정 방법 (참고)

> ⚠️ **MCP 지원 상태**: Hermes의 MCP 통합은 현재 **수동 설정 필요** 상태입니다. 막히면 슬랙 #ai-native-camp 에 문의.

> 🚨 **보안 경고**: 아래 예시의 토큰은 **플레이스홀더**입니다. 실제 토큰을 이 파일에 직접 박지 마세요 — 이 파일은 git 추적 중입니다. 실제 설정은 본인 PC의 `~/.hermes/config.json` (git 추적 X) 에만 박으세요.

`~/.hermes/config.json`에 아래 형태로 추가:

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_TOKEN": "<YOUR_GITHUB_TOKEN_HERE>"
      }
    },
    "notion": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-notion"],
      "env": {
        "NOTION_API_KEY": "<YOUR_NOTION_KEY_HERE>"
      }
    }
  }
}
```

> MCP를 추가한 뒤에는 `hermes gateway restart`로 재시작하세요.

## 8. 꿀팁 — Hermes 더 잘 쓰는 법

### 구체적으로 요청하기

나쁜 예:
```
보고서 써줘
```

좋은 예:
```
이번 주 마케팅 팀 주간 보고서 써줘.
형식: 이번 주 성과 / 다음 주 계획 / 이슈
톤: 대표님 보고용, 간결하게
분량: A4 반 페이지
```

### 맥락 먼저 제공하기

```
배경: 우리 서비스는 B2B SaaS 프로젝트 관리 도구야.
유저: 50인 이하 스타트업의 PM.
요청: 이탈률 줄이기 위한 리텐션 전략 3가지 제안해줘.
```

### 역할 부여하기

```
너는 10년차 프로덕트 매니저야.
아래 기능 스펙을 보고 빠진 점, 리스크, 개선 사항을 짚어줘.
```

### 출력 형식 지정하기

```
아래 내용을 표로 정리해줘:
| 항목 | 현재 | 목표 | 갭 |

[내용]
```

```
JSON 형식으로 응답해줘.
```

```
마크다운 형식으로, 제목 + 불릿 포인트로 정리해줘.
```

### 반복 작업은 cron으로

매번 같은 걸 요청하고 있다면 자동화하세요:

```
나 매일 아침에 "뉴스 요약해줘" 하잖아. 그냥 매일 9시에 자동으로 보내줘.
```

### 이전 대화 활용하기

```
아까 만든 PRD 기반으로 사용자 스토리 추가해줘.
```

```
어제 정리한 회의록에서 액션 아이템만 다시 뽑아줘.
```

### 피드백으로 개선하기

```
방금 답변 좀 더 간결하게 다시 써줘.
```

```
톤이 너무 딱딱해. 좀 더 캐주얼하게.
```

```
좋아, 이런 스타일로 앞으로도 계속 답변해줘.
```

### 모르면 물어보기

```
이거 너한테 시킬 수 있어? 슬랙 채널 메시지 읽는 것도 돼?
```

Hermes는 자기가 뭘 할 수 있고 없는지 솔직하게 알려줍니다.
