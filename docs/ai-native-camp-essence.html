01—왜 하는가
안 해도 되는 일을 발견하고, 제거하는 것
  • AI Native ≠ ChatGPT 잘 쓰기
  • AI Native ≠ 기존 업무에 AI 붙이기
  • AI Native = AI가 있다는 전제로 업무를 재설계
02—왜 지금
AI가 당신을 대체하는 게 아니라,
AI를 쓰는 사람에게 대체된다

"이런 것까지 되는구나"를 아는 것 — Unknown Unknowns 제거가 진짜 역량.

03—어떻게 안정적으로

운이 아니라 시스템으로

매번 새로 운에 맡기지 말고, 매번 같은 품질이 나오게 고정.

Model→ Context→ Agent→ Harness · 조종석

비결정적(랜덤) → 결정적(매번 같은 결과). Harness가 그 조종석.

08—항상 켜진 AI

터미널을 벗어나 — Hermes

Claude Code

정밀 수술. 내 컴퓨터 앞에 앉아서.

Hermes

항상 옆의 비서. 슬랙에서, 자동으로. 쓸수록 내 패턴을 배운다.

  • 자가학습 — 대화할수록 점점 정확
  • cron — "매일 9시에 ___" 한 문장으로 예약
  • 멀티에이전트 — 봇끼리 협력, 사람은 최종 확인
설치는 한 번: API 키·Slack 연결까지 아래 스킬이 다 안내합니다. (Windows는 START FIRST에서 깐 WSL 위에서)

09—한계 = 컨텍스트
AI는 "그거"를 모른다

"내 일정 정리해줘" — 사람은 알아듣지만 AI는 날짜·타임존·캘린더ID를 모른다.

안 되는 건 대개 무능이 아니라 컨텍스트 부재. 컨텍스트는 사람이 준다.

10—도구는 외부, 색은 우리 것

Harness vs Skill

엔진·차체 (Harness)

Claude Code · Hermes · Ouroboros

외부에서 가져온다. 우리가 만들지 않는다.

운전 가이드 (Skill·맥락)

매뉴얼 · 스킬 · 컨텍스트

우리 색. 도구에 우리 맥락을 입히는 데 집중.

KB

한 번 묻기(CC·Hermes) vs 계속 돌아가기(Ouroboros).

12—성장 경로

사다리는 안 변한다

L1AI한테 시킬 수 있다개인 생산성 ↑ — 먼저 익숙해진다
L2안 해도 되는 일을 발견한다업무 제거 — 핵심
L3AI 전제 프로세스를 만든다팀 운영 방식 변화
순서가 중요 — 도구를 못 쓰는데 "재설계하라"면 망상이 나온다. L1에 충분히 익숙해진 다음 L2.
