07—본질

AI는 "그거"를 모른다.

사람한테 "내 일정"이라 하면 다 알아듣지만 — AI는 다 모름.

  • 오늘이 며칠인지 모름 (모델 cutoff 시점)
  • Timezone이 KST인지 모름 (UTC로 검색해 빈 결과)
  • "내 캘린더"가 어느 calendar인지 모름 (primary? 회사? 구독?)

→ 사람이 하나하나 알려줘야 한다.
알잘딱깔센은 AI의 본질이 아니다.

12—왜 Ouroboros인가

한 번 묻기 vs 계속 돌아가기.

같은 Claude를 쓰는데 — AI를 굴리는 방식이 다르다. 그래서 결과가 다르다.

Claude Code · Hermes

한 번 묻고, 한 번 답

사람이 명령 → AI 답
사람이 검증 → 사람이 다시 명령

사람이 루프를 굴린다.
짧은 일·즉답에 강함

Ouroboros

스스로 돌아간다 🔄

사람이 한 번 명세
→ AI가 질문·실행·자가 검증
→ 부족하면 AI가 재시도

AI가 루프를 굴린다.
복잡한 일·여러 단계 필요한 일에 강함

이름 그대로 — 자기 꼬리를 무는 뱀. 자기가 자기를 검증한다.

💡 무거운 도구가 필요한 순간도 있다

Ouroboros = fat harness. "Thin harness" 트렌드의 정반대편.
왜 두꺼움? — 자기 질문·실행·검증·재시도를 다 하려면 메커니즘이 두꺼울 수밖에. 사용자 부담을 도구가 흡수.
두께 자체가 죄가 아님 — 일에 따라 가벼운 도구가, 어떤 일엔 무거운 도구가 정답.

→ 우리 캠프 = 둘 다 fat 인정하고 분담: 회사 색(자리 ①)은 우리, 도구 두께(자리 ②)는 외부.

13—자리 ②의 답

Ouroboros.

스스로 돌아가는 AI — 모호함 → 명확함 → 실행 → 자가 검증 → 재시도. github.com/Q00/ouroboros

"Stop prompting. Start specifying."
병목은 AI 능력이 아니라, 사람의 명확성.

5단계 파이프라인

interview
→
seed
→
run
→
evaluate
→
evolve
  • interview — "정확히 뭐 원해요?" 모호함 자동 추출
  • seed — 사용자 답 받아서 명세 자동 생성
  • run — 명세 기반 실행 (핵심)
  • evaluate — 결과 검증 → 실패 자동 감지 → 재시도
  • evolve — 다음번 자동 (부가 기능)
❓ "Hermes로는 안 되나요?"

Hermes = 간단한 한 줄 받는 비서 (받자마자 AI에 던짐)
Ouroboros = 큰 일을 받아 "정확히 뭐죠?" 묻고 실행하는 PM
→ 모호한 큰 일은 Hermes로 헛일. Ouroboros가 그 갭을 메움.

외부 오픈소스 Hermes 공식 지원 (Claude Code · Codex · OpenCode와 함께)
강사 maintain · 직접 설치 + 컨트리뷰션 가능
