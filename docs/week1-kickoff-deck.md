## 슬라이드 구성

### 1. 오프닝 — 왜 모였는가 (3분)

> "4주 후, 우리 조직의 업무 방식은 영구적으로 바뀐다."

- 이 캠프는 **교육이 아니다**
- 누가 가르쳐주는 게 아니라, **각자 AI와 대화하면서 발견**하는 과정
- 내가 해줄 수 있는 건 **방향**과 **도구**뿐
- 나머지는 여러분이 직접 해야 함

---

### 2. AI Native란? (5분)

```
AI Native ≠ ChatGPT를 잘 쓰는 것
AI Native ≠ 기존 업무에 AI를 붙이는 것
AI Native = AI가 있다는 전제로 업무를 재설계하는 것
```

**핵심 질문:**
> "지금 하고 있지만, 사실 안 해도 되는 일은 뭔가?"

- 예시 1: 매주 수동으로 만드는 리포트 → AI가 자동 생성하면?
- 예시 2: 학생에게 일일이 안내하는 것 → 안내 자체가 필요 없는 구조라면?
- **"더 잘하는 것"이 아니라 "안 하는 것"을 찾는 캠프**

---

### 3. 바이브코딩의 흐름 — 지금 어디까지 왔는가 (10분)

> AI 코딩의 진화 단계. 우리는 지금 "하네스" 시대에 와 있다.

```
Stage 1: Model (모델)
  └─ "AI가 코드를 짜준다"
  └─ ChatGPT, Claude에 질문 → 답변 복붙
  └─ 한계: 매번 컨텍스트를 직접 줘야 함

      ↓

Stage 2: Context (컨텍스트)
  └─ "AI가 내 상황을 안다"
  └─ Cursor, Copilot — 코드베이스를 읽고 제안
  └─ 한계: 한 파일, 한 작업 단위

      ↓

Stage 3: Agent (에이전트)
  └─ "AI가 스스로 판단하고 실행한다"
  └─ Claude Code — 터미널에서 코드 읽기/쓰기/실행/커밋
  └─ 한 번의 지시로 여러 단계를 자율 수행
  └─ 한계: 매번 처음부터 설명해야 함

      ↓

Stage 4: Harness (하네스) ← 지금 여기
  └─ "AI에게 역할과 규칙을 미리 세팅한다"
  └─ CLAUDE.md, Skill, MCP, Hook, Plugin, Agent Teams
  └─ AI가 우리 회사의 맥락, 도구, 프로세스를 알고 있는 상태
  └─ 지시가 아니라 "협업"이 되는 단계
```

**핵심 메시지:**
- Model 시대: "이거 해줘" → 복붙
- Context 시대: "내 코드 보고 해줘"
- Agent 시대: "알아서 해줘"
- **Harness 시대: "우리 방식대로 해줘"** ← 이게 AI Native

> "우리가 4주간 할 것은, 이 조종석을 우리 회사에 맞게 만드는 것이다."

### 5. 3개 원칙 (3분)

이 캠프 전체를 관통하는 원칙:

```
1. 액션 전에 문제
   → "뭘 할까" 전에 "왜 해야 하나"
   → /think-deeper 스킬로 구조화

2. 성공과 실패 동시에
   → Plan A만 세우지 않는다
   → 항상 "이게 안 되면?"을 같이 생각

3. 임기응변 체크
   → "이거 시스템인가 땜빵인가?"
   → 땜빵이면 OK, 근데 알고는 있어야 함
```

## 발표 노트

- 슬라이드는 텍스트 최소화, 키워드만 — 말로 설명
- 바이브코딩 흐름은 **단계별로 하나씩 보여주면서** 설명 (애니메이션 효과)
- "떠먹여주지 않는다"를 여러 번 반복 — 이게 기조
- 데모는 하지 않음 — 참가자가 직접 해봐야 의미 있음
- 시간이 남으면 Q&A, 부족하면 바로 실습으로
