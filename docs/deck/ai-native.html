00—정의

AI Native 란?

≠ 이런 게 아니다

ChatGPT를 잘 쓰는 것. 기존 업무에 AI를 덧붙이는 것.

= 이것이다

AI가 있다는 전제로 업무를 다시 설계하는 것.

장인이 아니라 감독입니다. 직접 만들지 않고, 시키고 검토합니다.

00—가져오는 것 ①

모른다는 것조차 모르는 자리를 줄입니다.

아는 것을 아는 것

Known Knowns — 이미 잘하고 있는 업무.

모르는 것을 아는 것

Known Unknowns — 찾아보면 됩니다. 이건 괜찮아요.

무의식적 능력

Unknown Knowns — 나도 모르게 하고 있는 것.

모른다는 것도 모르는 것

Unknown Unknowns — ← 여기를 줄이는 게 핵심입니다.

"이런 게 가능한지조차 몰랐다" → "이건 이미 누가 해놨네". 모른다는 걸 알기만 하면, 나머지는 AI한테 물어보면 되니까요.

디자인 안 해본 사람이

분석 안 해본 사람이

쿼리를 돌립니다.

일을 줄이는 게 끝이 아닙니다. 그 시간으로 뭘 새로 하게 되는지가 더 중요합니다.

00—가져오는 것 ③

직무에 얽매이지 않아도 됩니다.

내가 발견한 문제는, 내가 직접 해결을 시도할 수 있습니다. 남의 일이라고 넘기지 않아도 됩니다.

회사는 이 모든 시도를 환영하고 지원합니다. 실패해도 괜찮습니다. 시도하지 않는 것이 더 큰 손실입니다.

01—왜 그래야 하나

운이 아니라 시스템으로.

01
Model
같은 질문에 매번 다른 답 — 비결정적
02
Context
내 파일을 읽으니 맥락은 맞는데, 여전히 들쭉날쭉
03
Agent
실행까지 한다. 근데 빈 차 — 어디로 갈지 매번 다름
04
Harness
세팅된 차 = 조종석. 매번 같은 품질 — 결정적

규칙·도구·순서를 미리 앉혀둔 상태를 조종석이라고 부릅니다. 같은 차라도 세팅이 돼 있으면 매번 같은 데로 갑니다.

우리가 만들 것은 네 번째입니다. 도구를 하나 더 배우는 게 아니라, 내 조종석을 짜는 것입니다.

02—시작은 네 개

이 네 개가 전부의 시작입니다.

1 · Claude Code

AI가 내 컴퓨터에서 직접 실행합니다. 나머지 셋이 여기 올라갑니다.

2 · CLAUDE.md

AI에게 주는 매뉴얼. 내가 누군지 매번 설명하지 않게 됩니다.

3 · Skill

반복되는 일을 매번 같은 품질로. 「내 전용 명령어」입니다.

4 · MCP

노션·슬랙·웹검색 같은 외부 도구를 AI 손에 붙입니다.

각자 진도는 다릅니다. 자기 속도로 가되, 막히면 바로 손 드세요.

/ai-onboarding
02—왜 이 넷인가

네 개가 하는 일은 두 가지뿐입니다.

🎯 결정화 — 결과를 예측 가능하게

CLAUDE.md 는 AI가 나를 기억하게 하고, Skill 은 매번 같은 품질을 내게 합니다. 들쭉날쭉을 없애는 쪽.

🔌 확장 — 할 수 있는 걸 늘리기

MCP 는 노션·슬랙 같은 외부 도구를 붙입니다. Subagent·Hook·Plugin 도 이쪽. 손을 늘리는 쪽.

일곱 개를 외울 필요 없습니다. 「들쭉날쭉을 없애는 것」과 「손을 늘리는 것」 두 갈래만 기억하시면 됩니다.

02—첫 번째

AI는 내가 누군지 모릅니다.

매번 "나는 마케팅 하고, 우리 회사는 운전면허 학원이고…" 를 다시 설명하고 있다면, 그건 매뉴얼이 없다는 뜻입니다.

  • 내 직무와 요즘 하는 일
  • 자주 쓰는 도구와 말투 취향
  • 모를 것만 적습니다 — AI가 이미 아는 상식은 넣지 않습니다

200줄을 넘기지 마세요. 길수록 좋은 게 아니라, "왜 그렇게 하는지" 를 담을 때 결과가 좋아집니다.

02—두 번째

같은 일을 매번 같은 품질로.

좋은 프롬프트를 어제는 잘 썼는데 오늘은 기억이 안 난다 — 그걸 파일로 굳히는 게 스킬입니다.

  • 반복하는 일을 한 번 정리해두면 다음엔 명령 한 줄
  • 만드는 법도 AI에게 시키면 됩니다 — ___를 자동화하는 스킬 만들어줘
  • 스킬을 만들어주는 스킬도 있습니다 — /superpowers:writing-skills 가 구조를 잡고 검증까지 해줍니다

두 가지만 — 같은 걸 세 번 설명했으면 그건 스킬로 만들 때입니다. 그리고 만든 뒤 AI에게 「이 스킬 읽고 모호한 부분 알려줘」 를 시키면 품질이 확 올라갑니다.

3. 남이 만든 걸

먼저 찾는다

03—잘 쓰는 사람들

비결은 안 만드는 겁니다.

잘 쓰는 사람들은 더 열심히 만드는 사람이 아니라, 이미 있는 걸 먼저 찾는 사람입니다.

  • 내가 필요한 건 남도 필요했습니다
  • 찾아보면 대개 누가 만들어 놨습니다
  • 없을 때만 만듭니다
03—꿀팁

잘 쓰는 사람들의 네 가지 습관.

  • CLAUDE.md — AI가 모를 것만 넣기. 200줄 넘기지 않기
  • 스킬 — 설명(description)이 제일 중요합니다. 「왜」를 적으면 결과가 좋아집니다
  • 에러 — 에러 메시지를 그대로 붙여넣고 fix 한 마디. 과한 설명은 오히려 방해입니다
  • 컨텍스트 — 대화가 길어지면 /compact, 막히면 /clear 하고 새로 시작
/tips

제일 중요한 건 스스로 계속 찾는 것입니다. 이 말을 하는 지금도 더 좋은 도구가 나오고 있습니다. 내 팁도 /tips 에 보태주세요 — 팀 집단지성입니다.

03—어디서 찾나

설치 한 번이면 바로 씁니다.

  • 공개된 스킬 모음에서 검색
  • /plugin 으로 플러그인 설치
  • 회사 스킬은 Zeude 가 알아서 넣어줍니다 (다음 장)

남의 걸 써보고 나서 만들면, 훨씬 좋은 걸 만듭니다.

03—내가 만든 건 어디에

내 스킬을 팀 전체에 한 번에 배포합니다.

Zeude 대시보드 → Skills 탭 → 스킬 등록. 팀 전원이 다음 동기화 때 자동으로 받습니다.

⚠️ 옛 안내 정정 — 예전엔 "스킬을 KB 레포에 push 해서 공유한다" 고 했습니다. 지금은 Zeude 가 표준입니다. KB 레포에는 KB 데이터를 다루는 스킬만 둡니다.

4. 같이

배운다

04—최소한의 Git

세 줄만 알면 일단 굴러갑니다.

git pull                          # 남이 바꾼 것 받기
git add . && git commit -m "..."  # 내가 바꾼 것 묶기
git push                          # 올리기

원리는 나중에. 막히면 에러 메시지를 그대로 AI에게 붙여넣으세요. 대개 그게 제일 빠릅니다.

04—사례 공유

남이 한 걸 보면, 나도 할 수 있는 게 늘어요.

사례
직접 한 것을 보여준다
만든 사람이 화면 켜고 직접
곱씹기
어떻게 했나, 왜 그렇게 했나
내 일에도 써먹게 한 번 더
나눔
질문하고, 내 일에 붙여보기
"이건 나도 되겠는데" 한 줄씩

사례를 많이 보는 게 목적이 아닙니다. 하나를 끝까지 뜯어보는 게 목적입니다.

04—뜯어볼 때

굉장한 건 결과가 아니라, 막혔을 때 뭘 했나입니다.

  • 처음에 뭘 하려고 했나 — 원래 하던 방식은 뭐였나
  • 어디서 막혔나 — 그때 AI에게 뭐라고 물었나
  • 왜 그 방법이었나 — 다른 길은 왜 안 골랐나
  • 다시 한다면 — 어디를 줄일 수 있나

진행하는 사람이 챙길 것 — "잘됐다"에서 멈추지 말고 실패한 시도를 반드시 물어보세요. 거기에 남이 따라 할 수 있는 정보가 있습니다.

채운다

06—AI의 한계

AI는 "그거"를 모릅니다.

"내 일정 좀 봐줘" — 사람은 알아듣지만 AI는 못 알아듣습니다. 어느 캘린더인지, 어느 타임존인지, 오늘이 며칠인지를 사람이 알려줘야 합니다.

좋은 도구를 붙이면 AI가 알아서 다 해준다는 건 환상입니다. 채울 자리가 남습니다.

06—비어 있는 칸

회사 이야기는 AI가 압니다. 팀 이야기만 아무도 모릅니다.

우리 팀이 요즘 뭐에 꽂혀 있는지, 뭘 물어봐야 하는지, 어느 채널에 말을 걸어야 하는지 — 문서 어디에도 없습니다.

  • 회사 전체 이야기는 이미 정리돼 있습니다
  • 팀 단위 이야기만 각 팀이 직접 넣어야 합니다. 대신 써줄 사람이 없어요
  • 다음에 들어올 사람이 첫 주에 실제로 이걸 읽습니다

06—채울 것

네 가지만 적으면 됩니다.

  • ① 우리 팀이 뭐 하는 팀인지 — 직무 설명 말고, 요즘 실제로 뭘 하는지
  • ② 첫 주에 꼭 알아야 할 것 3개 — 모르면 헤매는 것들
  • ③ 누구에게 뭘 물어보나 — 이름 말고 역할로
  • ④ 우리 팀 용어 — 밖에서는 안 쓰는 말들

완벽하게 쓰려 하지 마세요. 한 칸이라도 채우는 게 빈 것보다 낫습니다.

07—약속 ①

사람에게 물어보기 전에, AI에게 먼저.

  • 파일 위치 · 히스토리 · 프로세스 — 사람이 아니라 AI가 답합니다
  • 사람에게 묻는 건 더블체크용입니다
  • 노션·데이터도 AI를 통해 찾을 수 있습니다

「이거 어디 있어요?」를 사람에게 묻지 않아도 되는 회사. 그게 목표입니다.

07—약속 ②

없으면 만들고, 만들면 공유한다.

1
먼저 찾는다
내가 필요한 건 남도 필요했다
2
없으면 만든다
스킬로 굳혀서 다음엔 명령 한 줄
3
만들면 나눈다
Zeude 에 올리면 팀 전원이 받는다

혼자 쓰고 끝내면 나만 빨라집니다. 나누면 팀이 빨라집니다.

07—약속 ③

문서를 사람이 보기 좋게 말고, AI가 보기 좋게.

예쁘게 정리한 문서보다, AI가 검색하고 이해할 수 있는 구조가 낫습니다. 그게 진짜 SSOT — 하나의 진실된 출처입니다.

  • 사람이 읽을 문서와 AI가 읽을 문서를 따로 만들지 않습니다
  • AI가 읽을 수 있으면 사람도 읽을 수 있습니다
  • 반대는 성립하지 않습니다
