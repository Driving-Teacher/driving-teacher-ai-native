## Week 1 — AI Native는 직무 대체가 아니라, 일하는 방식의 영구적 혁신

### 이번 주 핵심 메시지
지금 하고 있지만 사실 **안 해도 되는 일**을 찾아서, AI에게 시키고 검토하는 감독으로 변해야 한다.

### 다룬 것
- 이 캠프는 교육이 아니라 각자 AI와 대화하면서 발견하는 과정
- AI가 대체하는 게 아니라 **AI를 쓰는 사람에게 대체된다**
- AI Native = 업무를 **재설계**하는 것 (이미 가진 것에 AI 붙이는 게 아님)
- Unknown Unknowns을 줄이는 것 — "이런 것까지 되는구나"를 아는 게 역량
- Claude Code 선택 이유: AI가 내 컴퓨터에서 직접 실행 (놀러 온 게 아니라 출근한 것)
- 비결정적 → 결정적: Model → Context → Agent → **Harness(조종석)**

### 기억할 개념 3개
1. **AI Native** — 기존 업무에 AI 붙이는 게 아니라, AI가 있다는 전제로 업무를 재설계
2. **Harness (조종석)** — 운이 아니라 시스템으로 일하기, 매번 같은 품질
3. **Unknown Unknowns 제거** — "이런 것까지 되는구나"를 발견하는 것이 진짜 역량

### 핵심 액션
- **Claude Code** — AI가 내 컴퓨터에서 직접 실행
- **Memory (CLAUDE.md)** — Claude에게 주는 매뉴얼
- **Skill (/think-deeper 같은)** — 반복되는 작업을 매번 같은 품질로
- **MCP** — 채널톡, 노션, 웹검색 등 외부 도구 연결

## Week 2 — 혼자가 아닌 같이, 팀의 지혜로 시작

### 이번 주 핵심 메시지
Claude를 더 잘 쓰는 법은 **공동 경험** 속에서 배운다. 숙제 나누고, 스킬 함께 만들고, Git으로 공유한다.

### 다룬 것
- 숙제 발표 (AskUserQuestion으로 구조화)
- 꿀팁 5가지 (CLAUDE.md, 스킬, 에러, 컨텍스트)
- 스킬·플러그인 찾기 (awesome-skills.com, knowledge-work-plugins)
- 스킬 만들기
- 역할별 추천 도구 (`docs/recommended-tools.md`)
- Git 최소 생존 키트 (clone, pull, push)
- 페어 실습 (회사 문제 함께 풀기)

### 기억할 개념 3개
1. **CLAUDE.md 200줄 규칙** — Claude가 모를 것만 넣고, "왜"를 담으면 결과 좋아짐
2. **knowledge-base 전략** — 내 스킬을 `driving-teacher-knowledge-base`에 push → 팀 전원 즉시 사용
3. **Git 3줄 세트** — `git pull` → `git add . && git commit -m "..."` → `git push`

### 핵심 액션
- AskUserQuestion으로 발표 내용 구조화 + HTML로 만들기
- awesome-skills.com 또는 /plugin으로 남이 만든 스킬 찾아 설치
- 페어 실습: 짝과 60분간 회사 문제 1개를 AI로 풀고 KB에 push
- 에러 메시지로 트러블슈팅 (`gh auth login`, `git pull` 등)

## Week 3 — 내 AI를 키우자 (Hermes Agent + Zeude)

### 이번 주 핵심 메시지
**터미널을 벗어나 슬랙에서 자동으로 일해주며**, 쓸수록 내 업무 패턴을 배우는 AI를 만든다.

### 다룬 것
- Zeude — 팀 AI 대시보드 (리더보드, 스킬 통계, 비용, 인사이트)
- Claude Code vs Hermes (정밀 수술 vs 항상 옆의 비서)
- Hermes 셋업 (Mac curl 설치, Slack App 연결)
- 직무별 유스케이스 (CS / 개발 / 마케팅 / 기획)
- cron 자동화 (매일/매주 예약 작업)
- 멀티에이전트 (봇끼리 대화)

### 기억할 개념 3개
1. **자가학습 루프** — 대화할수록 Hermes가 내 패턴 기억해서 점점 정확
2. **cron 자동화** — "매일 9시에 ___" 한 문장으로 반복 작업 예약
3. **멀티에이전트** — 봇들이 일 넘기며 협력, 사람은 최종 확인만

### 핵심 액션
- **/hermes-setup** — 슬랙 봇 설치 + Slack App 토큰 연결
- **/zeude-setup** — 팀 AI 대시보드 + 텔레메트리
- **Hermes에 업무 요청 5개** — 본인 직무 작업을 슬랙 DM으로
- **자동 예약 1개** — cron으로 매일 또는 매주 반복

## Week 4 — 도구는 외부, 색은 우리 것

### 이번 주 핵심 메시지
4주를 데이터와 회고로 돌아보고, **AI와 함께 일하는 우리의 방식을 선언**한다.

### 다룬 것
- 지난 4주 타임라인 (체험 → 페어 → Hermes → 회고·선언)
- Zeude 데이터로 본 사용량 패턴
- Hermes 1주 사용 후 피드백 (A/B/C/D 자가 평가)
- "캘린더 조회 안 됨" 사례로 배우는 AI의 한계
- **Harness vs Skill 자동차 비유**
- 회사 색을 채울 두 자리: ① 회사 매뉴얼(KB) ② 복잡한 일 명세(Ouroboros)
- 한 번 묻기(CC/Hermes) vs 계속 돌아가기(Ouroboros)
- Ouroboros 5단계 파이프라인

### 기억할 개념 3개
1. **Harness vs Skill** — 도구(자동차 엔진)는 외부에서, 매뉴얼(운전 가이드)은 우리가 작성
2. **AI는 "그거"를 모른다** — "내 일정"이라 하면 사람은 알지만 AI는 모름. 컨텍스트(날짜/타임존/캘린더ID)를 사람이 알려줘야 함
3. **Ouroboros의 본질** — 모호함을 명확함으로 자동 변환. 자기 질문·실행·검증·재시도 (자기 꼬리를 무는 뱀)

### 핵심 액션
- **/ouroboros:interview** — 본인 직무에서 "AI에 맡기고 싶은 일 1개" 모호함 자동 추출
- **/ouroboros-setup** — 플러그인 설치 (약 5분)
- **/kb-setup → /hermes-kb-setup** — Claude Code와 Hermes에 회사 KB 연결
- **AI Native 선언** — "____ 제거하고 그 시간에 ____하겠다" + 1주 실천 + 회고
