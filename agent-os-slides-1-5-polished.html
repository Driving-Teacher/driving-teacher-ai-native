Slide 04 · Boundary Map

Claim / Evidence / Verdict
— 셋을 분리한다

"끝났다"는 보고는 입력에 불과합니다.
AgentOS는 셋을 따로 다룹니다 —
실행 증거, verifier 판정, replay 기록.

Planning Surface

Seed Contract의 goal · AC · 제약을 정의하고,
profile에 맞춰 AC를 말단 단위까지 쪼갠다.

Agent Runtime

도구를 실행하고 claim을 만든다.
하지만 여기서 만들어진 claim은 내부에만 머무른다.

Verification Surface

Evidence Manifest(파일·명령·artifact)만 받아
verifier가 검사하고, 판정을 store에 기록한다.

Claim은 Agent Runtime 내부에만 존재합니다.
완료 여부는 Evidence Manifest → Verifier → Store 순서로만 확정됩니다.
Slide 05 · Three Tracks

AgentOS Phase 1, 세 개 트랙으로 완성한다

Track A · Execution & Verification

fat-harness 기본 적용, 타입이 명시된 증거, verifier PASS.

→ run 하나를 끝까지 완성하는 트랙

Track B · Autonomy & Self-Healing

실패해도 멈추지 않는 실행, ledger로 복구, 관찰 AC와 실행 AC 분리.

→ auto 모드를 완성하는 트랙

Track C · Core Kernel

Workflow IR 재생, 플러그인 lifecycle, runtime skill 가이드.

→ OS surface를 완성하는 트랙
